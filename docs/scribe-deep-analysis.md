## 1. 产品全貌

### 1.1 公司背景

Scribe（scribehow.com）成立于 **2020 年**，总部位于美国旧金山，定位为「AI 驱动的流程文档自动化平台」。核心使命：让任何人无需技术写作能力，只需正常操作软件，即可自动生成图文并茂的分步操作指南。

- **创始人**：Jennifer Smith（前 McKinsey & Company、Greylock Partners）与 Aaron Podolny（前 Google 工程师）
- **团队背景**：创始团队兼具顶级咨询公司商业洞察与 Google 级工程能力，这解释了 Scribe 在「用户体验简洁度」与「AI 引擎精准度」上的双重优势
- **Crozdesk 评分**：94/100（Workflow Management 类目前三），用户满意度 96/100
- **融资情况**：具体融资轮次与金额未完整公开披露，但产品采取 Freemium 模式且已有成熟的 Pro/Enterprise 付费体系，推测至少完成 A 轮以上融资

### 1.2 产品线总览

Scribe 覆盖 **三端一平台** 的全场景产品矩阵：

| 产品形态 | 核心定位 | 适用场景 | 能力边界 |
|---------|---------|---------|---------|
| **Chrome/Edge 扩展** | 轻量即时生成 | 网页端操作指引、SaaS 功能教程、线上流程记录 | 仅录制浏览器内操作，不支持本地软件和桌面系统 |
| **桌面端（Windows/Mac）** | 全场景录制覆盖 | 本地软件操作指南、系统设置教程、IT 运维流程 | 支持浏览器 + 本地应用 + 桌面操作，覆盖 Chrome 扩展无法触及的场景 |
| **Web 端** | 内容管理中枢 | 团队知识库沉淀、文档协作编辑、分享权限管控、数据统计分析 | 无录制能力，负责生成文档的二次编辑、存储、分发、数据看板 |
| **平台 API** | 企业集成 | 嵌入企业内部系统（CMS/LMS/知识库）、自动化工作流 | Enterprise 专属，支持 SSO/SCIM 等企业基础设施对接 |

**关键设计理念**：录制端（扩展/桌面）与编辑管理端（Web）分离。录制端追求极致轻量、无感知；编辑端追求丰富协作与分发能力。两端通过云端实时同步。

## 2. 技术架构深度拆解

### 2.1 Chrome 扩展架构：Content Script + Background Service Worker + 消息通信

Scribe 的 Chrome 扩展采用 **Manifest V3** 规范，核心由三层组成：

#### 2.1.1 Content Script（内容脚本层）

运行在用户访问的网页上下文中的注入脚本，负责：

- **DOM 事件监听**：通过 `addEventListener` 全局监听 `click`、`input`、`change`、`keydown` 等用户交互事件
- **元素定位与特征提取**：当事件触发时，提取目标元素的语义信息：
  ```javascript
  // 伪代码示例：捕获点击事件并提取上下文
  document.addEventListener('click', (e) => {
    const target = e.target;
    const context = {
      tagName: target.tagName,
      innerText: target.innerText?.substring(0, 100),
      id: target.id,
      className: target.className,
      ariaLabel: target.getAttribute('aria-label'),
      xpath: getXPath(target),     // 生成唯一路径用于截图定位
      boundingRect: target.getBoundingClientRect(), // 用于截图裁剪区域计算
      timestamp: Date.now()
    };
    chrome.runtime.sendMessage({ type: 'USER_ACTION', payload: context });
  });
  ```
- **截图触发**：检测到有效用户操作后，通过消息通道通知 Background 层执行截图；Content Script 自身不直接截图（受 CSP 限制）
- **URL 变化监听**：通过 `MutationObserver` 或 `popstate`/`hashchange` 事件检测页面跳转，确保 SPA 应用中的路由切换不被遗漏
- **输入脱敏**：对 `input[type="password"]` 和敏感字段（如信用卡号、SSN），自动标记为「需脱敏」，截图中以 `***` 替换实际值

#### 2.1.2 Background Service Worker（后台服务层）

运行在独立线程中，不直接访问网页 DOM，负责：

- **全局状态管理**：维护录制状态机（`IDLE → RECORDING → PROCESSING → DONE`）
- **截图捕获**：通过 `chrome.tabs.captureVisibleTab()` API 获取当前标签页的可见区域截图，结合 Content Script 传来的 `boundingRect` 进行精准裁剪
- **事件日志聚合**：接收来自所有标签页的 Content Script 消息，按时间序列聚合为原始操作日志（Raw Action Log）
- **AI 引擎调度**：录制停止后，将原始操作日志发送至 Scribe 云端 AI 服务，等待步骤生成结果
- **与 Web 端同步**：通过 WebSocket 或 HTTP 将生成的 Scribe 文档推送到用户 Web 工作区

#### 2.1.3 消息通信机制

Content Script 与 Background Service Worker 之间通过 Chrome Extension Messaging API 通信：

```
Content Script ──chrome.runtime.sendMessage()──> Background SW
Background SW  ──chrome.tabs.sendMessage()────> Content Script
```

- **单向事件上报**：Content Script → Background SW（高频，每个用户操作触发一次）
- **指令下发**：Background SW → Content Script（低频，如「开始录制」「暂停」「停止」）
- **长连接**：使用 `chrome.runtime.connect()` 建立 `Port` 长连接，避免高频 `sendMessage` 导致的性能开销

**Manifest V3 关键配置示例**：

```json
{
  "manifest_version": 3,
  "name": "Scribe",
  "permissions": ["storage", "activeTab", "scripting"],
  "host_permissions": ["<all_urls>"],
  "background": {
    "service_worker": "background.js"
  },
  "content_scripts": [{
    "matches": ["https://*/*", "http://*/*"],
    "js": ["content.js"],
    "run_at": "document_end"
  }]
}
```

### 2.2 桌面端录制引擎：操作行为捕获 vs 屏幕录制双模式

桌面端（Windows/Mac）是 Scribe Pro/Enterprise 的核心差异化能力，采用 **双模式混合架构**：

#### 2.2.1 模式一：操作行为捕获（Operation Capture）

优先路径。通过 OS 级 API 捕获系统事件：

- **Windows**：通过 `SetWindowsHookEx` 注册全局鼠标/键盘钩子，结合 `UI Automation` API 获取目标控件语义信息（按钮文本、输入框标签等）
- **Mac**：通过 `CGEventTap` 捕获鼠标/键盘事件，结合 `Accessibility API`（`AXUIElement`）获取 UI 元素属性
- **窗口追踪**：监听活动窗口切换事件（Windows: `EVENT_SYSTEM_FOREGROUND`，Mac: `NSWorkspaceDidActivateApplicationNotification`），自动关联操作步骤与对应应用程序

**行为捕获的数据结构**：

```json
{
  "step_id": 12,
  "timestamp": 1690900000000,
  "action_type": "click",
  "target": {
    "application": "Microsoft Excel",
    "window_title": "Book1 - Excel",
    "element_type": "button",
    "element_text": "Bold",
    "position": { "x": 342, "y": 89 }
  },
  "screenshot_bounds": { "x": 300, "y": 50, "w": 200, "h": 100 }
}
```

#### 2.2.2 模式二：屏幕录制兜底（Screen Recording Fallback）

当操作行为捕获无法获取语义信息时（如老旧 Win32 应用、自定义绘制控件），降级为低码率屏幕录制：

- 使用平台原生截屏 API 周期性抓取屏幕（约 2-3 FPS）
- 通过帧差分析（Frame Differencing）自动检测画面变化，仅在变化超过阈值时保留帧
- 录制文件以临时缓存形式存储，AI 处理后自动清理

**双模式对比**：

| 维度 | 操作行为捕获 | 屏幕录制兜底 |
|------|------------|------------|
| 步骤可编辑性 | 高（每步可独立编辑文字/截图） | 低（需额外后处理拆分帧） |
| 资源占用 | CPU < 5%，内存 < 100MB | CPU 10-15%，内存 200-400MB |
| 语义信息丰富度 | 丰富（控件文本、类型、位置） | 无（仅为像素数据） |
| 适用场景 | 标准 Windows/macOS 应用 | 老旧/自定义 UI 应用 |

#### 2.2.3 录制容错机制

- **无效操作过滤**：自动识别并丢弃误操作（如 50ms 内的连续点击、非功能区域的空白点击）
- **暂停/继续**：用户可随时暂停录制（跳过不需要记录的步骤），恢复后无缝衔接
- **管理员权限处理**：对于 Task Manager 等需要管理员权限的应用，Scribe 引导用户以管理员身份运行桌面端，确保事件捕获不丢失

### 2.3 Web 端编辑器架构

Web 端是 Scribe 的内容管理主阵地，采用现代化前端架构：

#### 2.3.1 整体架构

```
┌─────────────────────────────────────────┐
│              React SPA                   │
├─────────────────────────────────────────┤
│  状态管理：Redux / Zustand               │
│  路由：React Router                      │
│  UI 组件库：自研设计系统                 │
├─────────────────────────────────────────┤
│  实时协作：WebSocket / CRDT             │
│  云端存储：AWS S3（截图）+ PostgreSQL    │
│  搜索：Elasticsearch（全文索引）         │
├─────────────────────────────────────────┤
│  AI 服务层：NLP 模型 API                 │
└─────────────────────────────────────────┘
```

#### 2.3.2 编辑器核心功能模块

- **步骤编辑器**：左侧边栏展示步骤列表，支持拖拽排序、合并、删除；主画布区域展示当前步骤截图与文字
- **截图编辑**：Canvas 渲染截图，叠加标注层（箭头、高亮框、文字标签），支持像素级位置调整
- **富文本编辑**：步骤描述支持 Markdown 内联编辑，自动保存（Debounce 500ms）
- **版本控制**：每次保存生成新版本快照，支持任意版本回溯与 Diff 对比
- **评论系统**：文档浏览者可在每个步骤下方添加评论，作者收到通知后快速迭代

#### 2.3.3 关键技术决策

- **自动保存机制**：编辑操作通过 Debounce 合并后自动触发保存，避免用户丢失编辑内容
- **离线支持**：当前版本**不支持离线编辑**，所有操作依赖网络连接 —— 这是用户核心槽点之一
- **响应式布局**：文档查看页面对移动端友好，但**编辑功能仅在桌面端可用**

## 3. 编辑器 UI/UX 详解

### 3.1 侧边栏布局

Scribe 编辑器采用经典的 **左右分栏** 布局：

```
┌──────────────┬──────────────────────────┐
│              │                          │
│  步骤列表    │     主画布区域           │
│  (侧边栏)    │   （当前步骤截图 +       │
│              │    文字描述）            │
│  Step 1 ●───│                          │
│  Step 2 ●   │   [ 截图预览 ]           │
│  Step 3 ○   │                          │
│  Step 4 ○   │   步骤描述文本           │
│  ...        │   编辑工具栏             │
│              │                          │
└──────────────┴──────────────────────────┘
```

- **左侧边栏**：垂直排列步骤卡片缩略列表，当前选中步骤高亮
- **主画布**：展示选中步骤的完整截图（宽度自适应，最大宽度约 800px）和文字描述
- **顶部工具栏**：分享按钮、导出下拉菜单、编辑/预览切换、设置

### 3.2 步骤卡片结构

每个步骤卡片由以下元素组成（从上到下）：

```
┌─────────────────────────────────────┐
│  (1) 蓝色圆形步骤号                  │
│       ●  Step 3                     │
│                                     │
│  (2) 步骤标题（AI 自动生成）         │
│       Click the "Save" button       │
│                                     │
│  (3) 步骤描述（可折叠详细说明）       │
│       Navigate to the top-right     │
│       corner of the page and click  │
│       the blue "Save" button...     │
│                                     │
│  (4) 全宽截图                        │
│  ┌─────────────────────────────┐   │
│  │   [页面截图，含自动标注]     │   │
│  │   → 橙色箭头指向按钮        │   │
│  │   ┌──────────┐              │   │
│  │   │  Save    │ ← 高亮框     │   │
│  │   └──────────┘              │   │
│  └─────────────────────────────┘   │
│                                     │
│  (5) 提示区（可选）                  │
│       💡 Tip: Make sure to save     │
│       before closing the window.    │
└─────────────────────────────────────┘
```

**设计细节**：

- 步骤号使用 **蓝色圆形徽章**（`background: #2563EB; border-radius: 50%; color: white`），这是 Scribe 品牌视觉的核心识别元素
- 截图默认**智能裁剪到操作区域**（非全屏），减少视觉噪音；用户可切换查看完整截图
- 截图与文字之间的间距约 16px，保持呼吸感
- 步骤间以分隔线或间距区分，滚动浏览时平滑过渡

### 3.3 标注系统

Scribe 的标注系统分为 **自动标注** 和 **手动标注** 两层：

#### 3.3.1 自动标注（AI 生成，录制完成后自动添加）

- **橙色圆形高亮**：在截图中用橙色半透明圆环（`border: 3px solid #F97316; border-radius: 50%`）标记点击位置，这是 Scribe 最标志性的视觉语言
- **自动箭头**：从操作区域边缘指向具体点击/输入位置的橙色箭头，箭头样式统一（线宽 2px，箭头大小 8px）
- **输入框高亮**：当步骤涉及输入操作时，用半透明橙色矩形框高亮输入字段区域

#### 3.3.2 手动标注（Pro 用户可编辑）

- **移动标注位置**：点击截图上的「铅笔」图标进入编辑模式，可拖拽箭头/高亮到新位置
- **添加文字标签**：在截图上叠加自定义文字说明框
- **添加自定义形状**：矩形、圆形、自由线条
- **替换截图**：上传本地图片替换自动生成的截图

#### 3.3.3 标注样式统一性

Pro 团队版支持自定义标注样式（箭头颜色、高亮颜色、字体），全团队保持一致。这确保了所有输出文档的视觉品牌统一性。

### 3.4 敏感信息脱敏机制

Scribe 的脱敏能力是其企业级安全的核心卖点，分为三级：

| 级别 | 触发方式 | 覆盖范围 | 适用版本 |
|------|---------|---------|---------|
| **自动识别** | AI 自动检测 | 100+ 类 PII/PHI 数据（邮箱、电话、信用卡号、SSN、地址等） | Pro 及以上 |
| **手动脱敏** | 用户在编辑器中点击模糊按钮 | 任意截图区域 | Free 及以上 |
| **强制脱敏** | 管理员设定全局脱敏策略 | 全团队所有文档自动执行 | Enterprise |

**技术实现**：

1. AI 模型在截图生成时并行执行 OCR + NER（命名实体识别），检测敏感信息并标记坐标
2. 前端 Canvas 层在渲染截图时，对标记区域的像素应用高斯模糊（`blur radius: 15px`）
3. 脱敏操作不可逆（模糊后的像素数据覆盖原始数据），确保分享后的文档无法还原敏感信息
4. Enterprise 管理员可配置「强制脱敏策略」：即便作者未手动触发，系统也强制对所有分享文档执行脱敏

## 4. AI 引擎三层架构

Scribe 的 AI 能力是其核心护城河，按功能维度分为三层：

### 4.1 第一层：步骤自动生成层（Step Generation Layer）

**输入**：原始操作日志（Raw Action Log）—— 包含时间戳、操作类型、目标元素信息、截图

**处理流程**（四阶段流水线）：

```
录制完成
    │
    ▼
Phase 1: Capture（捕获）
    - 事件监听器收集 click/input/navigate 事件
    - 每步截图 + boundingRect 坐标
    - 输出：Raw Action Log (JSON)
    │
    ▼
Phase 2: Analysis（分析）
    - Computer Vision：识别截图中操作的具体 UI 元素
    - NLP：将原始数据（如 click on element id="login-submit"）
      翻译为自然语言（"Click the 'Log In' button"）
    - 操作意图识别：区分「点击按钮」「输入文本」「选择下拉」「页面跳转」
    │
    ▼
Phase 3: Assembly（组装）
    - 自动裁剪截图到操作区域
    - 叠加橙色箭头/高亮标注
    - 拼接步骤描述 + 截图 → 步骤卡片
    │
    ▼
Phase 4: Refinement（优化）
    - 过滤无效/重复步骤
    - 合并相邻相似操作（如连续两次点击同一按钮 → 合并为一步）
    - 输出：完整 Scribe 文档
```

**准确率**：公开资料显示，标准 Web 应用场景下步骤描述准确率 > 90%。复杂操作（拖拽、右键菜单、弹窗交互）准确率约 70-80%，是当前主要优化方向。

### 4.2 第二层：内容优化层（Content Optimization Layer）

在基础步骤生成之后，AI 执行高级内容优化：

- **自动标题生成**：基于操作流程的上下文，生成 SEO 友好的文档标题（如 "How to Create a Report in Salesforce"）
- **流程摘要生成**：在文档开头自动生成 2-3 句的概述段落，帮助读者快速理解文档目的
- **多语言翻译**：一键将整个 Scribe 文档翻译为 100+ 种语言，保持截图标注与文字描述同步翻译
- **步骤合并建议**：AI 识别语义上可合并的连续步骤（如 "Click File" → "Click Save" 可合并为 "Click File > Save"），主动建议用户合并

### 4.3 第三层：格式生成层（Format Generation Layer）

将同一流程内容输出为不同格式，满足多场景分发需求：

| 输出格式 | 生成方式 | 适用场景 |
|---------|---------|---------|
| **交互式 Scribe（默认）** | 原生 Web 格式，支持步骤展开/折叠 | 在线分享、嵌入知识库 |
| **PDF 手册** | 自动排版为 A4 页面，保留截图+文字 | 线下培训、合规存档 |
| **Markdown 文档** | 纯文本 + 图片引用 | Git 仓库、技术文档 |
| **HTML 嵌入代码** | iframe 友好格式 | CMS、LMS 集成 |
| **Confluence 页面** | 直接发布到 Confluence Space | Atlassian 生态用户 |
| **视频教程** | 将步骤序列渲染为带旁白的视频 | 异步培训（功能预告，尚未完整体验） |

## 5. 完整用户闭环

Scribe 的用户流程覆盖从内容生产到价值衡量的完整链路：

### 5.1 阶段一：录制（Capture）

```
用户操作：安装扩展/桌面端 → 点击"Start Capture" → 正常完成操作流程 → 点击"Stop Capture"
系统行为：后台事件监听 → 截图捕获 → 操作日志聚合 → 发送至 AI 引擎
耗时：等于实际操作耗时（零额外开销）
```

关键体验：3 秒倒计时后开始录制，给予用户心理准备时间。录制过程中，Chrome 扩展图标变为红色录制状态指示器。

### 5.2 阶段二：AI 生成（AI Generation）

```
系统行为：AI 分析操作日志 → 生成步骤文字 → 裁剪截图 → 添加标注 → 组装文档
耗时：5-15 秒（取决于步骤数量）
输出：在新标签页打开完整 Scribe 文档
```

### 5.3 阶段三：编辑器（Edit）

```
用户操作：审查 AI 生成内容 → 修改错误描述 → 调整步骤顺序 → 替换截图 → 添加提示
协作功能：团队多人可同时编辑（实时协作），评论可 @ 团队成员
版本管理：每次保存自动生成版本快照，支持回退任意历史版本
```

### 5.4 阶段四：分享/导出（Share & Export）

| 分享方式 | 权限粒度 | 适用场景 |
|---------|---------|---------|
| **公开链接** | 任何人可访问 | 外部客户文档 |
| **团队链接** | 仅团队成员 | 内部 SOP |
| **密码保护链接** | 需输入密码 | 敏感流程 |
| **限时链接** | 设置过期时间 | 临时分享 |
| **嵌入代码** | iframe 嵌入任意网页 | 帮助中心、知识库 |
| **PDF/Markdown/HTML 导出** | 离线文件 | 合规存档、邮件发送 |

### 5.5 阶段五：反馈迭代（Feedback & Iteration）

- **评论系统**：浏览者可在每个步骤下方添加评论、提出问题
- **作者通知**：邮件/应用内通知作者有新反馈
- **快速更新**：作者直接编辑文档，所有分享链接自动更新为最新版本
- **版本 Diff**：查看任意两个版本之间的差异

### 5.6 阶段六：数据看板（Analytics）

Pro/Enterprise 用户可在 Web 端后台查看：

- **文档浏览量**：每篇 Scribe 的总浏览人次
- **完成率**：读者从头到尾完整浏览的比例（需开启追踪）
- **步骤停留时间**：哪些步骤读者耗时最长（可能说明该步骤描述不清晰）
- **用户反馈统计**：正面/负面反馈趋势
- **团队使用统计**：各成员的文档创建量、活跃度

#### 路径 A：扩展录制 → 编辑 → 分享（最常用）

```
[用户在目标网页] → ① 点击浏览器工具栏 Scribe 图标（P1）
→ ② 点击 "Start Capture"（P2），侧边栏显示闪烁红点
→ ③ 按正常流程操作目标网页 [可选 Pause / Voice Transcription]
→ ④ 点击 "Complete Capture" → P5 AI 生成过渡态
   AI 引擎处理：去重 → 自动裁剪 → AI 文字生成 → UI 元素名识别
→ ⑤ 自动进入 P6 编辑器（新标签页）
   左侧：步骤列表栏（序号+缩略图+文字摘要）
   右侧：当前步骤大图+完整描述
→ ⑥ 编辑精修（Edit 模式）：
   修改文字 / 合并步骤 / 删除步骤 / 添加步骤 / 拖拽排序 / 截图标注(Pro) / 模糊脱敏(Pro)
→ ⑦ 点击 "Share" → P8 分享弹窗
   A) Copy Link：生成唯一 URL，实时更新

   C) Export：PDF / HTML / Markdown
→ ⑧ 分享后进入 P7 查看器页面
```

#### 路径 B：桌面端录制 → 编辑 → 分享

桌面端通过 OS 级全局监听录制任意应用（Pro 独占）。流程与路径 A 一致，关键差异：
- 截图是全屏/当前窗口，进入编辑器后 AI 自动裁剪聚焦区域
- 需要 Admin 权限录制系统级应用
- 桌面端 Pro/Enterprise 独占，免费版只能录浏览器

#### 路径 C：多文档 Pages 聚合流程

Dashboard → Create Page → 拖拽已有 Scribes 到画布 → 添加 Text Block/Divider/Image → Share

#### 路径 D：查看者体验流程

点击分享链接 → P7 只读查看器：左侧步骤列表 + 右侧详情 + 顶部进度条 → 可 Duplicate / Comment

#### 路径 E：迭代更新流程

Dashboard 点击已有 Scribe → Edit → 修改步骤/Recapture 截图/插入新步骤 → 保存 → 分享链接自动同步

## 11. 国产化全维度分析

> **核心命题**：将 Scribe 从美国 SaaS 产品改造为适配中国市场的桌面操作录制工具

### 11.1 总览：国产化改造全景图

### 11.8 合规与数据安全国产化

#### 核心合规要求

| 法规/标准 | 要求 | Flowio 应对 |
|----------|------|------------|
| **《网络安全法》** | 个人信息境内存储 | 本地优先架构天然合规 |
| **《数据安全法》** | 数据分类分级保护 | 敏感截图自动识别脱敏 |
| **《个人信息保护法》** | 最小必要原则 + 用户同意 | 录制前明确告知采集范围 |
| **等保 2.0（二级）** | 身份鉴别/访问控制/安全审计 | 企业版提供 SSO + 操作日志 |
| **信创适配** | 国产 CPU/OS 兼容 | 统信 UOS + 麒麟 OS（未来） |

#### 数据处理对比

```
Scribe 数据流：
用户操作 → 浏览器扩展采集 → AWS 美区服务器 → AI 处理 → AWS S3 存储
↑ 全部数据出境，中国合规风险高

Flowio 数据流：
用户操作 → Rust 本地录制引擎 → 本地 SQLite → 本地 AI 推理
                                 ↓
                          用户主动触发云同步
                                 ↓
                          阿里云 OSS（中国区）
↑ 数据本地化，不主动上传
```

### 11.10 中国竞品生态分析

中国市场上没有 Scribe 的完全对标产品。竞品要么是偏 RPA 的脚本录制回放，要么是手动的文档编辑。**Flowio 有机会定义这个品类。**

| 产品 | 类型 | 核心能力 | 与 Scribe 差距 |
|------|------|---------|--------------|
| Keymouse Go | 键鼠录制回放 | 录制鼠标键盘，重放操作 | 无 AI 步骤生成，无截图标注，纯 RPA |
| 按键精灵 | 自动化脚本 | 录制+脚本，主要面向游戏 | 无文档生成能力，偏自动化 |
| 自动脚本精灵（安卓） | 手机 RPA | Lua 脚本 + OCR 识别 | 纯移动端，RPA 向 |
| 飞书/钉钉 帮助文档 | 文档平台 | 手动编写帮助文档 | 无自动录制生成能力 |
| WPS 录制宏 | Office 自动化 | VBA 宏录制 | 仅 Office 内，无跨应用能力 |
| 芦笋 / Getodo | 录屏工具 | 视频录制+云端分享 | 视频体量大，无步骤化 |

#### 潜在威胁

| 威胁 | 出现概率 | 应对 |
|------|---------|------|
| 飞书/钉钉 自建类似能力 | 中 | 做好独立产品体验 + API 集成 |
| WPS 推出操作录制功能 | 中 | 聚焦跨应用场景 |
| Scribe 进入中国 | 低 | 抢占先发优势 |
| 开源项目兴起 | 高 | 靠 AI 引擎壁垒 + 用户体验 |
