> 对标：Scribe（scribehow）2026 年现状。语音转录 = Pro 档；翻译 = Enterprise 档。
> 本文档是唯一验收依据。开发前用户确认；确认后一次性实现，不打补丁式迭代。

## 一、竞品事实（已核实，2026-09-03）

| 能力 | Scribe 做法 | 我们对标后的取舍 |
|---|---|---|
| 语音输入 | 录制前开开关 → 边操作边说话 → 自动检测语言 → 文字落到对应步骤；可与打字混用 | 采纳「落到对应步骤」；落点改为**追加**到步骤描述（见 F1） |
| 翻译 | 教程内点 Translate → 只翻标题+步骤描述（截图不动）→ 14 种语言 → 分享/导出均带翻译 | 采纳「只翻文本、截图不动」；改为**译文副本**，不覆盖原文（见 F2） |

## 二、F1 语音输入（桌面端 + 扩展端）

### 2.1 用户故事
录制教程时不想回头补打说明：打开语音开关，边操作边说"这一步点这里是为了…"，录完后每一步的描述里自动多出我说的话。

### 2.2 行为契约（全场景）

| # | 场景 | 预期行为 |
|---|---|---|
| V1 | 开关默认状态 | **关闭**。状态记忆到设置（下次录制沿用上次选择） |
| V2 | 开启开关 | 录制浮窗出现🎙录音中标识（呼吸动效）；不弹任何打断式窗口 |
| V3 | 麦克风权限被拒 | 开关自动弹回关闭 + 非阻塞 toast：「需要麦克风权限才能用语音输入」，并给出系统设置入口提示；**录制本身不受影响，正常继续** |
| V4 | 每次截图 | 记录当前音频时间戳（截图事件 ↔ 音频位置对齐） |
| V5 | 停止录制 | 进入转写阶段：浮窗显示「语音转写中…」；**转写失败不阻塞教程生成**（见 V9） |
| V6 | 转写落点 | 每段转写文字**追加**到对应步骤描述末尾，格式：`\n\n【语音】xxx`；步骤原本的 AI 生成内容**绝不动** |
| V7 | 某步无语音/纯静音 | 该步骤描述不变，不出现空【语音】标记 |
| V8 | 语言 | 自动检测，中英混合、常见方言均可（GLM-ASR 特性）；不设语言选择项 |
| V9 | 单步转写失败（网络/429/超段） | 该步骤跳过，描述不变；汇总 toast：「N 步语音转写失败（原因）」；失败原因落 debug log —— **与 AI 生成失败的处理方式对齐** |
| V10 | 用户一句话跨越多步 | 按截图时间点切片，**整句归到切片起点所在步骤**（不拆句） |
| V11 | 单段 > 60 秒 | 按 55s 硬切为多段分别送 ASR，结果按顺序拼接（GLM-ASR 单段上限 60s） |
| V12 | 关闭开关录制 | 行为与现在完全一致，音频管线零开销 |
| V13 | 录制中途关闭开关 | 从关闭时刻起不再采集；已采集部分照常转写 |
| V14 | 隐私 | 音频仅在开关开启时采集；仅用于转写，不落库不备份，转写完成即删临时文件 |

### 2.3 技术方案

**桌面端（Tauri）**
- 前端 getUserMedia + AudioWorklet 采集 PCM → 交 Rust 写入临时 WAV（`hound`）。
- 截图事件携带音频时间戳（从音频轨道启动时刻起算）。
- 停止后 Rust 按时间戳切片 →（>60s 再按 55s 细分）→ 逐段调 ASR。
- ASR：`POST https://open.bigmodel.cn/api/paas/v4/audio/transcriptions`，`model=glm-asr`，multipart；**复用现有智谱 Key 与 429 退避重试逻辑**（http.rs）。

**扩展端（MV3）**
- 采集：widget/浮窗所在上下文 getUserMedia + MediaRecorder（content script 可用）；关闭浏览器中途休眠等场景以"已采集的完整段"为准。
- 转写：**必须走服务端代理**（Key 不能进扩展包）。新增 `flowio.cn/api/ai/asr`（Node 小服务，持智谱 Key，Caddy 反代），扩展上传 wav/mp3 → 返回文字。
- ⚠️ 依赖项：需要先部署该代理服务（部署清单见 §四）。

## 三、F2 教程翻译（桌面端编辑器 + 导出）

### 3.1 用户故事
教程做完了想给英语/其他语言的同事看：编辑器里点「翻译」选语言，得到一份译文副本，预览和导出都能切换。

### 3.2 行为契约

| # | 场景 | 预期行为 |
|---|---|---|
| T1 | 翻译范围 | **仅教程标题 + 步骤标题 + 步骤描述**；截图、标注、UI 一律不动（与 Scribe 一致） |
| T2 | 保存形式 | 存为该教程的**译文副本**（按语言存储），原文永不修改 |
| T3 | 重复翻译同一语言 | 覆盖旧译文副本（弹确认：「已存在 English 译文，重新翻译将覆盖」） |
| T4 | 翻译中 | 按钮 loading；可关闭弹窗但翻译继续后台跑 |
| T5 | 翻译失败 | toast 报原因（含 429 退避后的最终失败）；原文与已有译文不受影响 |
| T6 | 预览/导出 | 语言切换器（原文 / 已有译文语言列表）；导出 DOCX/HTML/PDF/MD 均以当前所选语言文本走现有导出管线，**截图不变** |
| T7 | 上传网站 | 上传时携带所选语言副本（本期只保证桌面上传正文原文；多语言上传为 P2，见 §四） |
| T8 | 编辑译文 | 本期译文**只读**；重新生成即覆盖。编辑译文为 P2 |
| T9 | 删除教程 | 连同所有译文副本一起删 |

### 3.3 技术方案
- 桌面 sqlite：`recordings` 加 `translations` JSON 字段（`{lang: {title, steps:[{title,desc}]}}`），NULL 安全读取（吸取 target_app 教训）。
- 翻译调用：Rust 端批量把文本送 GLM 文本模型（一次请求打包全部步骤，输出结构化 JSON），复用智谱 Key 与退避重试。
- 目标语言首期：English / 简体中文 / 日语 / 韩语 / 西班牙语（后续在设置里可扩）。
