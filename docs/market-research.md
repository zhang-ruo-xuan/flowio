### 1.2 产品定位

Scribe 定位为 **AI 驱动的工作流文档与智能平台**。核心价值主张：用户执行操作 → 自动生成图文并茂的步骤指南。

三个核心能力：
1. **自动捕获**：记录用户在浏览器/桌面应用中的每个操作（点击、输入、截图）
2. **AI 增强**：自动生成步骤标题、描述文字、SOP 编排建议
3. **一键分享**：链接、嵌入、PDF/HTML/Markdown 导出

### 1.3 定价策略

| 版本 | 价格 | 用户数 | 核心能力 |
|------|------|--------|----------|
| Basic（免费） | $0 | 个人 | 仅浏览器扩展，基础分享 |
| Pro Personal | $23/月/人 | 1 人起 | 桌面+浏览器捕获，品牌定制，截图编辑，PDF/HTML/MD 导出 |
| Pro Team | $15/seat/月 | 5 人起（$59/月起） | 团队协作（评论），基础管理 |
| Enterprise | 定制报价 | 按需 | SSO、PII/PHI 自动脱敏、多团队管理、高级数据治理、语言翻译 |

**定价特点**：
- 免费版功能极简，仅限浏览器——强引导转化
- Pro Personal 定价偏高（$23/月），适合重度个人用户
- Pro Team 起始 5 人（$59/月），适合小型团队
- Enterprise 无公开定价，靠大客户销售

### 1.5 技术路径

Scribe 的技术架构遵循"核心录制纯工程实现 + AI 仅做增值"原则：

```
用户操作 → 浏览器扩展（Chrome/Edge）或桌面应用 → 事件捕获（点击/输入/滚动）
    → 自动截图（每个操作前后）→ 步骤序列化
    → AI 增强（标题生成/描述优化/SOP 编排/翻译）
    → 输出（链接分享/PDF/HTML/视频）
```

**关键洞察**：
- 录制核心流程是纯技术实现，不依赖 AI
- AI 仅用于增值功能：生成步骤标题、优化描述文字、SOP 流程编排、多语言翻译
- 此架构保证了核心功能的低成本和可靠性

## 二、StepSnap 技术评估

> 基于 `D:\Projects\flowio\docs\stepsnap-analysis.md` 的分析结论

### 2.1 项目定位

StepSnap 是基于 Tauri 2 的开源桌面录屏文档工具，技术栈为 Rust + React + TypeScript。它是 Scribe 的开源替代方案中技术实现最接近的一个。

### 2.2 优势

| 维度 | 评价 |
|------|------|
| DOM 事件捕获 | ⭐⭐⭐⭐⭐ 核心能力强，rdev 跨平台稳定，双通道（键盘+无障碍API）文本捕获 |
| 截图机制 | ⭐⭐⭐⭐⭐ xcap 全屏/区域截图 + after-frame 稳定截图 |
| UI 元素识别 | ⭐⭐⭐⭐ Windows UIA + macOS Accessibility，获取控件名/类型/宿主应用 |
| 原生覆盖层 | ⭐⭐⭐⭐ 独立透明窗口实现点击高亮，无窗口装饰、鼠标穿透 |
| Tauri 集成 | ⭐⭐⭐⭐ State 管理 + emit 通信模式成熟 |
| 密码保护 | ⭐⭐⭐⭐ 自动检测 secure 字段，值替换为哨兵 |

### 2.3 短板

| 维度 | 评价 |
|------|------|
| UI/UX | ❌ 界面老旧，开源项目感强，无专业设计 |
| 中文支持 | ❌ 无中文界面，无中文步骤生成 |
| AI 集成 | ❌ 仅基础 API 调用，无国产大模型支持 |
| 商业化 | ❌ 无付费体系、用户管理、云端协作 |
| 导出格式 | ❌ 仅基础格式，无品牌定制 |
| 移动端 | ❌ 无移动端录制能力 |
| 易用性 | ❌ 安装配置门槛高，面向开发者 |

### 2.4 复用策略（已确定）

**可复用**（纯技术逻辑）：
- `recorder.rs` — 全局输入监听引擎
- 截图机制 — xcap + after-frame
- `accessibility.rs` — Windows UIA 元素识别
- `overlay.rs` — 原生覆盖层窗口逻辑（仅逻辑，不参考配色）
- Tauri State 管理 + emit 通信模式

**不可复用**：
- 任何 React 组件、CSS 样式、布局、图标、配色
- 所有 UI 层面的代码

**结论**：StepSnap 是录步的最佳技术起点——核心录制引擎成熟可用，但 UI 和产品化层面需要从零构建。

### 3.2 国产化替代需求

中国企业面临的独特需求：

| 需求 | 说明 |

## 四、目标市场与竞争定位

### 4.1 录步的定位

```
录步 = Scribe 的国产替代 + 中文原生体验 + 国产大模型深度集成
```

| 维度 | Scribe | 录步（目标） |
|------|--------|-------------|
| 目标市场 | 全球（以美国为主） | 中国及中文用户 |
| 语言 | 英文为主 | 中文原生 |
| AI 模型 | OpenAI/自有 | 智谱/通义千问/DeepSeek（国产） |
| 定价 | $23/月个人，$15/seat团队 | ¥29/月个人，¥79/seat/月团队 |
| 数据合规 | 海外服务器 | 国内服务器，数据不出境 |
| UI 设计 | 西式 | 国产化（类飞书/钉钉风格） |
| 桌面框架 | Electron | Tauri 2（更轻量） |

### 4.2 SWOT 分析

#### 优势 (Strengths)

- **中文原生**：AI 生成的中文步骤描述质量远超 Scribe 的机器翻译
- **国产大模型深度集成**：智谱 GLM-4-flash 成本极低（¥0.02/次），DeepSeek V4/通义千问为备选
- **轻量架构**：Tauri 2 比 Electron 体积小 10 倍，性能更好
- **合规优势**：支持私有化部署，数据不出境，符合国内监管要求
- **定价优势**：¥29/月 vs Scribe $23/月（约 ¥165），性价比极高
- **技术复用**：StepSnap 的录制引擎可直接复用，缩短开发周期

#### 劣势 (Weaknesses)

- **产品成熟度不足**：从零起步，需要时间迭代功能
- **品牌知名度为零**：无市场认知，需要从冷启动开始
- **团队资源有限**：无法与 Scribe $1.3 亿融资的团队规模竞争
- **生态缺失**：无第三方集成、API、插件市场

#### 机会 (Opportunities)

- **蓝海市场**：国内无成熟竞品，先行者优势巨大
- **国产替代浪潮**：信创政策推动企业采购国产软件
- **大模型普及**：国产大模型能力快速提升，AI 生成质量将持续改善
- **远程办公常态化**：企业对异步文档工具的需求持续增长
- **出海潜力**：先占领中文市场，后续可拓展东南亚/日韩等东亚市场

#### 威胁 (Threats)

- **Scribe 进入中国**：若 Scribe 推出中文版并降价，将形成直接竞争
- **大厂入局**：字节跳动（飞书）、阿里（钉钉）可能推出类似功能
- **开源替代**：新的开源项目可能降低录制引擎的获取门槛
- **AI 成本波动**：大模型 API 价格未来可能上涨

### 4.3 差异化战略

录步的核心差异化战略为"三个国产化"：

```
1. AI 国产化  →  智谱/通义千问/DeepSeek，数据不出境
2. 体验国产化 →  中文原生流程描述，符合国人操作习惯的 UI
3. 合规国产化 →  支持私有化部署，满足金融/政务等行业要求
```

## 六、结论与建议

### 6.1 核心结论

1. **市场存在**：中国企业培训市场 8000 亿+，流程文档工具是明确刚需，且国内无成熟竞品
2. **差异化明确**：中文原生 + 国产大模型 + Tauri 2 轻量架构，构成清晰壁垒
3. **技术可行**：StepSnap 提供成熟录制引擎，录步只需聚焦 UI 重做和 AI 集成
4. **定价合理**：¥29/月的定价远低于 Scribe $23/月（¥165），在中国市场有竞争力
5. **时间窗口**：Scribe 尚未进入中国，国内大厂尚未布局，应尽快推出 MVP

### 6.2 战略建议

- **先打中文市场**：集中资源做深中文体验，不急于国际化
- **免费版做减法**：免费版仅保留核心录制+基础导出，AI 功能全部锁定为付费
- **企业版优先做合规**：私有化部署 + 数据不出境是金融/政务客户的硬门槛
- **AI 成本控制**：默认使用智谱 GLM-4-flash（¥0.02/次），确保毛利健康
